# Временная недоступность каталога — отчёт

Дата проверки: 10 октября 2026 года.

## Обнаруженные проблемы

- Каталог различал ошибки категорий и товаров, но показывал общие сообщения без контекста. Ссылки для повтора вели на `/catalog` и сбрасывали параметры поиска вместо повторного запроса.
- Главная превращала неудачные запросы в пустые массивы. Посетителю сообщалось об отсутствии товаров, хотя каталог мог быть недоступен.
- Общий API-клиент уже имел AbortController и тайм-ауты, но браузерный каталог использовал несколько автоматических попыток с паузами. Состояние загрузки могло затягиваться; отменённые запросы также могли повторяться.
- Неправильный ответ с HTTP 200 мог восприниматься как пустой каталог.
- При ошибке категорий контейнер сохранял колонку боковой панели, даже когда самой панели не было.

## Решение

Сохранены существующие состояния каталога и логика поиска, фильтров, сортировки и пагинации. Общие ветки ошибок заменены одним компонентом `CatalogLoadError`, который также используется в зависимых от API блоках главной страницы. Пустой каталог и неизвестная категория сохраняют свои обычные состояния.

Композиция использует имеющиеся кремовые и розовые цвета, Playfair Display и Manrope, кружевной разделитель, размеры кнопок, радиусы и состояния фокуса. На широком экране иллюстрация расположена слева от текста; до 600 px элементы располагаются вертикально. Размеры иллюстрации ограничены 280 px на широком экране и 180 px на мобильном, пропорции остаются квадратными. При повторе блок остаётся на месте, кнопка сохраняет размеры и отключается. Успешно загруженные блоки главной остаются видимыми, пока проверяется соединение.

Все новые пользовательские тексты украинские, в том числе на английском маршруте. Компонент помечен `lang="uk"`; остальные тексты сайта сохраняют существующее поведение локализации.

## Обработка ошибок

| Ситуация | Поведение |
| --- | --- |
| Соединение не установлено или прервано; тайм-аут соединения или чтения ответа | Тематический текст с предположением о перебоях; причина конкретного сбоя не утверждается. |
| HTTP 408, 502, 503, 504 | Тематическое состояние временной недоступности сервиса. |
| HTTP 500 и другие серверные ошибки | «Фігурки поки за лаштунками»; пояснение, что сервер ответил, но не смог передать товары, без предположений об отключении света. |
| HTTP 429 | «Дай каталогу хвилинку»; просьба подождать перед повтором. |
| Другие ошибки запросов, неправильный JSON или отсутствие массива `items` | «Не вдалося відкрити каталог»; нейтральная просьба повторить попытку. |
| Корректный ответ с пустым массивом товаров | Обычное состояние пустого каталога; сообщение о недоступности не показывается. |
| Уход со страницы или смена запроса | Предыдущий запрос отменяется. Отмена не считается отключением сервера и не запускает повторные попытки. |
| Повторная попытка | Запрос выполняется заново с прежними параметрами; повторные нажатия блокируются синхронной проверкой и отключённой кнопкой. |
| Успешное восстановление | Каталог возвращается автоматически после успешного повторного запроса, без перезагрузки документа. |

Один браузерный запрос категорий, списка товаров или витрины главной имеет тайм-аут **10 секунд**, включая чтение тела ответа, и одну попытку. Каталог сохраняет последовательную загрузку категорий и товаров; при необходимости ограничения номера страницы существующая логика выполняет дополнительный запрос. Главная запрашивает категории и товары параллельно. Повторные запросы используют `no-store`, поэтому браузер обращается к API заново. Серверные параметры кеширования и повторов сборки сохранены.

Сетевые ошибки помечаются в существующем API-клиенте. Исключение TypeError из другого кода само по себе не считается сетевым сбоем. Технические сообщения сервера, адреса и диагностические данные не используются в новом компоненте. Существующее безопасное отображение сетевых ошибок в остальных потребителях API учитывает новую метку.

Иллюстрация, стили и текст поставляются фронтендом и не запрашиваются у бэкенда. Декоративное изображение имеет пустой `alt`; заголовок связан с семантической секцией, статус озвучивается через `role="status"`, кнопка работает с клавиатуры. Анимация повтора учитывает существующее глобальное правило `prefers-reduced-motion`.

```bash

pnpm --filter storefront test
cd apps/storefront
node test/build-stage2b-fixture.mjs
```

При необходимости `CHROMIUM_EXECUTABLE` задаёт путь к имеющемуся Chromium; `SMOKE_OUTPUT` сохраняет JSON-отчёт, а `SMOKE_SCREENSHOTS` — снимки экрана.

## Ограничения проверки

Реальный бэкенд не отключался и не изменялся. Его успешные ответы, сетевые отказы и HTTP-ошибки имитировались локально; production-запросы в изолированной сборке не выполнялись. Сама причина реального отключения света или интернета не определяется фронтендом.

Проверялась используемая проектом статическая Pages-сборка; отдельная standalone-сборка не запускалась. Проверки в Safari/Firefox, ручное прослушивание экранным диктором и работа на физических мобильных устройствах не выполнялись. Контраст, семантика, клавиатурный запуск, уменьшение движения и мобильная геометрия проверены в коде/Chromium.

Установленный системный Node.js 20 не поддерживал флаг `--experimental-strip-types`; тесты выполнены с временным Node.js 22. Полный набор тестов и Chromium запускались вне песочницы, поскольку ограничения песочницы препятствовали дочерним процессам и браузеру. Отсутствующая конфигурация ESLint остаётся единственным препятствием штатной проверке линтером.
